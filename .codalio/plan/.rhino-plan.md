# Implementation Plan: EngageBlog (ContentReach)

## Summary

ContentReach is a multi-tenant blog publishing platform for content teams: create/edit/publish
text and video posts, manage a media library, view reach & audience analytics, and administer
users, integrations, system settings and health reports. The backend is Rhino v4 on Rails
(blueprint-first CRUD + a small set of hand-written Extras); the client is a Rhino React SPA
whose screens are the user-approved prototype under `.codalio/ui-prototype/`.

## Models (reference)

Source of truth is the blueprint files under `server/.rhino/blueprints/`.

### `Post`
- Ownership: organization-scoped (`belongs_to_organization: true`), soft deletes, audit trail.
- Key fields: `title` (required), `slug`, `content`, `category`, `tags` (json), `status`
  (default `draft`), `read_time_minutes`, `view_count` (default 0), `published_at`,
  `scheduled_at`, `user_id` (author).
- Relationships: belongsTo Organization, belongsTo User, hasMany Video, hasMany AnalyticsData.
- Implementation notes after blueprint: add `rhino_search :title, :content, :category`;
  `rhino_includes :user, :videos`; computed attribute `has_video` (see Extras).

### `Video`
- Ownership: organization-scoped, soft deletes.
- Key fields: `title` (required), `description`, `url` (required), `media_type` (default
  `video`), `format`, `file_size`, `resolution`, `bitrate`, `thumbnail_url`,
  `duration_seconds`, `status` (default `ready`), `post_id` (**nullable** — media-library
  assets are standalone), `user_id`.
- Relationships: belongsTo Organization, belongsTo User, belongsTo Post.
- Implementation notes: computed attribute `duration` (MM:SS display string).

### `AnalyticsData`
- Ownership: organization-scoped.
- Key fields: `event_type` (required), `visitor_id`, `event_data` (json), `recorded_at`
  (required), `post_id` (nullable).
- Relationships: belongsTo Organization, belongsTo Post.

### `Integration`
- Ownership: organization-scoped, audit trail.
- Key fields: `name` (required), `category`, `description`, `connected` (default false),
  `client_id`, `api_key`, `auto_sync` (default true).

### `ApiToken`
- Ownership: organization-scoped, audit trail.
- Key fields: `name` (required), `token_prefix` (required), `last_used_at`.

### `Webhook`
- Ownership: organization-scoped, audit trail.
- Key fields: `url` (required), `events` (json), `status` (default `pending`).

### `SystemSetting`
- Ownership: organization-scoped, audit trail, one row per organization.
- Key fields: `company_name`, `custom_domain`, `contact_email`, `transcode_preset`
  (default `1080p`), `max_upload_size` (default `1024mb`), `auto_captions` (default true),
  `auto_chapters` (default true), `enforce_2fa` (default true),
  `session_timeout_minutes` (default 60), `sso_provider`.

### `SystemReport`
- Ownership: organization-scoped, audit trail.
- Key fields: `report_type` (required), `parameters` (json), `status` (default `pending`),
  `generated_at`, `summary` (json).

### `RolePermission`
- Ownership: organization-scoped, audit trail.
- Key fields: `capability` (required), `description`, `role_key` (required), `enabled`
  (default false).

## Extras (NOT covered by blueprint — develop stage implements these by hand)

1. **`User` schema extension** — `User#` (core model).
   - Rule: add `first_name`, `last_name`, `approved` (boolean, default false),
     `profile_completed` (boolean, default false) to the core `users` table.
   - Where: `server/db/migrate/*_add_profile_fields_to_users.rb`,
     `server/app/models/user.rb` (validations + `rhino_additional_hidden :api_token`).
   - AC: AC-69.

2. **`Post#has_video` computed attribute** — `Post#show`/`#index`.
   - Rule: `has_video` is true when the post has ≥1 associated video.
   - Where: `server/app/models/post.rb` (`rhino_computed_attributes`).
   - AC: AC-66.

3. **`Post` publish transition** — `Post#update`.
   - Rule: setting `status` to `published` sets `published_at` to now when blank; setting
     `status` to `scheduled` requires `scheduled_at`.
   - Where: `server/app/models/post.rb` (`before_save` callback + custom validation).
   - AC: AC-5, AC-6.

4. **`Post` slug auto-generation** — `Post#store`/`#update`.
   - Rule: when `slug` is blank, derive it from `title` (lowercase, hyphenated, unique per org).
   - Where: `server/app/models/post.rb` (`before_validation`).
   - AC: AC-66.

5. **`Post` ownership check** — `Post#update`/`#destroy`.
   - Rule: a `content_manager`/`editor` may only update/destroy posts they authored; `admin`
     may act on any post in the organization.
   - Where: `server/app/policies/post_policy.rb`.
   - AC: AC-2, AC-10.

6. **`Video#duration` display string** — `Video#show`/`#index`.
   - Rule: emit `duration` as `MM:SS` derived from `duration_seconds`.
   - Where: `server/app/models/video.rb` (`rhino_computed_attributes`).
   - AC: AC-67.

7. **Analytics aggregate endpoint** — `GET /api/{organization}/analytics/summary`.
   - Rule: tenant-safe aggregate returning `total_impressions`, `unique_readers`,
     `engagement_rate`, `watch_time_hours`, `daily_series[]`, `leaderboard[]` for a
     `range` + `content_type` filter. Must use `Rhino.query(AnalyticsData)` /
     `Rhino.query(Post)` (never raw model queries) and gate on `analytics_data.index`.
   - Where: `server/app/controllers/api/analytics_controller.rb`,
     `server/config/routes.rb`.
   - AC: AC-68, AC-40, AC-41, AC-42, AC-43.

8. **Analytics event recording** — `AnalyticsData#store`.
   - Rule: a public/authenticated `POST /api/{organization}/analytics_data` records a `view`
     event with `visitor_id`; unique readers = distinct `visitor_id`.
   - Where: `server/app/models/analytics_data.rb` (validation + default `recorded_at`).
   - AC: AC-40.

9. **System health endpoint** — `GET /api/{organization}/system/health`.
   - Rule: admin-only endpoint returning `api_gateway`, `db_replica`, `video_storage`,
     `security_perimeter` status objects (the keys the prototype reads).
   - Where: `server/app/controllers/api/system_controller.rb`, `server/config/routes.rb`.
   - AC: AC-62, AC-52.

10. **Daily backup job + restore endpoint** — `SystemReport`/`SystemSetting`.
    - Rule: a scheduled job (`BackupJob`) writes a daily backup record; admin can trigger
      `POST /api/{organization}/system/restore` from the most recent backup.
    - Where: `server/app/jobs/backup_job.rb`, `server/app/controllers/api/system_controller.rb`,
      `server/config/schedule.rb` (or `config/recurring.yml`).
    - AC: AC-54, AC-55, AC-56.

11. **Role-based access control enforcement** — all models.
    - Rule: `content_manager`/`editor`/`contributor` are denied every `/admin/*` resource
      (`integrations`, `api_tokens`, `webhooks`, `system_settings`, `system_reports`,
      `role_permissions`); unauthorized attempts are logged.
    - Where: `server/app/policies/*_policy.rb` (per-model gates) +
      `server/app/models/scopes/*_scope.rb` for row filtering.
    - AC: AC-57, AC-58, AC-65.

12. **Contributor read-only scope** — `Post`/`Video`.
    - Rule: `contributor` may only `index`/`show`; `store`/`update`/`destroy` are denied
      (enforced by the blueprint permission matrix + policy `super`).
    - Where: `server/app/policies/post_policy.rb`, `server/app/policies/video_policy.rb`.
    - AC: AC-57.

13. **Integration status indicator + webhook ping** — `Integration`/`Webhook`.
    - Rule: `connected` toggles the status indicator; `POST /api/{organization}/webhooks/{id}/ping`
      performs a test dispatch and updates `status`.
    - Where: `server/app/controllers/api/webhooks_controller.rb`, `server/config/routes.rb`.
    - AC: AC-46, AC-47, AC-70.

14. **Multi-role seeds** — `db/seeds.rb`.
    - Rule: create a `Role` row for each of `admin`, `content_manager`, `editor`, `contributor`
      and a `UsersRole` per demo user (Sarah Chen → content_manager, Alex Thorne → admin, plus
      an editor and a contributor) in the demo organization; seed `sample_data` posts/videos/
      analytics.
    - Where: `server/db/seeds.rb`.
    - AC: AC-71.

## Implementation order (recommended stage flow)

Aligned with `--pipeline`:

1. **Plan** — this artifact set (YAMLs, plan, criteria, index, handoff).
2. **Develop** — phase A: `bundle exec rails rhino:blueprint` + migrations (incl. the User
   profile-fields migration). Phase B: implement **Extras** (computed attributes, publish
   transition, aggregate + health endpoints, backup job, policies/scopes, seeds). Phase D:
   write backend unit + integration tests for every AC.
3. **UI / UI-Integration** — build the 10 screens listed above; vendor the prototype JSX
   verbatim and wire the `data_contract` / `action_contract` from `ui-handoff.json`.
4. **Test** — run `bundle exec rails test` to confirm green and tighten anything broken.
5. **Review** — PRD compliance + test/coverage report.
